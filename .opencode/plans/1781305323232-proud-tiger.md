# Plan: XBRL Definition Linkbase Anchoring (Custom→Standard Tag Mapping)

## Goal

Add the ability to fetch and parse XBRL **definition linkbases** from per-filing EDGAR packages to extract custom→standard tag anchoring (e.g. `aapl:MyCustomTag` → `us-gaap:Revenues`). Keep the existing companyfacts API pipeline for values; augment it with per-filing definition linkbase data for anchoring.

## Current State

- **Companyfacts API** (`data.sec.gov/api/xbrl/companyfacts/CIK{cik}.json`): Returns flat observations with no linkbases, definition arcs, or anchoring metadata.
- **Filing index**: Fetched via HTML `-index.htm` page (parsed with regex). Can discover `EX-101.DEF` documents.
- **Filing documents**: Accessed via `Url::CikAccessionDocument(cik, accn, filename)` → `raw_request()` → `response.text()`.
- **XML parsing**: Uses `quick-xml` v0.39.2 (streaming event-based pull parser). Already used for Form 4, 13F, N-PORT, Atom feed.
- **No XBRL definition linkbase parsing exists**. No `.xsd` or `-def.xml` files are fetched or parsed.

## Data Source

Each SEC filing's EDGAR directory contains:
```
https://www.sec.gov/Archives/edgar/data/{CIK}/{accn_unformatted}/
  - {company}-{date}.xsd       (extension schema → custom element definitions)
  - {company}-{date}_def.xml   (definition linkbase → anchoring arcs)
  - {company}-{date}_pre.xml   (presentation linkbase)
  - {company}-{date}_cal.xml   (calculation linkbase)
```

These are listed in the filing index as `EX-101.SCH`, `EX-101.DEF`, etc.

The definition linkbase XML contains `<link:definitionArc>` elements with `xlink:arcrole="http://xbrl.org/arcrole/2008/definition-arcrole/general-special"` that link standard GAAP concepts to custom extension concepts.

## Implementation

### 1. Add `Url::CikAccessionIndexJson` variant

**File:** `src/enums/url_enum.rs`

Add URL variant that produces:
```
https://www.sec.gov/Archives/edgar/data/{CIK}/{accn_unformatted}/{accn_formatted}-index.json
```

The JSON index is cleaner to parse than the HTML version and has structured document entries with `name`, `type`, `description`, and `size`.

### 2. Add XBRL-specific filters to `FilingDocument` / `FilingIndex`

**File:** `src/models/filing_document.rs`

Add methods:
- `FilingDocument::is_definition_linkbase()` → `document_type == "EX-101.DEF"`
- `FilingDocument::is_extension_schema()` → `document_type == "EX-101.SCH"`
- `FilingIndex::definition_linkbase()` → find EX-101.DEF document
- `FilingIndex::extension_schema()` → find EX-101.SCH document
- `FilingIndex::xbrl_documents()` → all EX-101.* documents

**File:** `src/models.rs` — register the new module.

### 4. Create definition linkbase parser

**NEW file:** `src/parsers/parse_xbrl_definition_linkbase.rs`

Parse XBRL `-def.xml` using `quick-xml` (already in dependencies):

1. Collect all `<link:loc>` elements → map `xlink:label` → parsed concept from `xlink:href` (split on `#`)
2. Collect all `<link:definitionArc>` elements → map `xlink:from`/`xlink:to` labels + `xlink:arcrole`
3. Join arcs to locators to produce `(custom_tag, standard_tag, arcrole)` tuples
4. Handle `general-special` as the primary anchoring arcrole

### 5. Create extension schema parser (simplified)

**NEW file:** `src/parsers/parse_xbrl_extension_schema.rs`

Parse the `EX-101.SCH` file to extract custom element declarations. Needed to:
- Know the namespace prefix (e.g. `aapl`) from the `targetNamespace`
- Get element metadata: name, substitutionGroup, type, balance, periodType

Use `quick-xml` to parse `<xsd:element>` declarations and `<xsd:schema>` attributes.

### 6. Create fetch function

**NEW file:** `src/network/fetch_xbrl_anchoring.rs`

```rust
pub async fn fetch_custom_tag_anchoring(
    client: &SecClient,
    company_tickers: &[Ticker],
    ticker: &TickerSymbol,
) -> Result<DataFrame, Box<dyn Error>>
```

Algorithm:
1. Fetch companyfacts JSON (reuse `fetch_us_gaap_fundamentals` logic but access raw JSON directly instead of re-parsing the full DataFrame)
2. Identify fact categories that are **not** standard namespaces (`us-gaap`, `dei`, `srt`, `invest`, `country`, `stpr`, `naics`, `sic`, `currency`, `ecd`, `utr`, `xref`)
3. For each custom namespace (e.g. `aapl`), group observations by `accn` → identify which filings have custom tags
4. For each unique filing (accn) with custom tags:
   a. Fetch `-index.json` → find EX-101.DEF and EX-101.SCH documents
   b. Fetch and parse EX-101.DEF (definition linkbase)
   c. Optionally fetch EX-101.SCH for namespace resolution
5. Build a DataFrame with the anchoring mappings
6. Return the DataFrame (with ticker, cik, accn, custom_tag, standard_tag, arcrole columns)
