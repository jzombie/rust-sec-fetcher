## Part 1 — FixtureKind variants for XBRL exhibits

### Background

The existing refresh binary (`src/bin/refresh_test_fixtures.rs`) already has fixture kinds for `CompanyFacts`, `ThirteenF` (by accession), `Form4Xml` (by accession), etc.  The same pattern can fetch individual XBRL exhibits from a specific filing.

### New FixtureKind variant

Add a single parametric variant:

```rust
enum FixtureKind {
    // … existing variants …
    /// Any named document within a specific filing.
    /// `accession` = the filing's accession number.
    /// `doc_type`  = the SEC document type to discover via the filing index
    ///               (e.g. "EX-101.CAL", "EX-101.DEF", "EX-101.LAB", "EX-101.SCH").
    /// The harness fetches the filing index, finds the matching document,
    /// then downloads it.
    FilingDocument {
        accession: &'static str,
        doc_type: &'static str,
    },
}
```

### Implementation in refresh binary

1. Add `FilingDocument { accession, doc_type }` to `FixtureKind`.
2. In the URL-building `match`, add a new arm:
   - Build a `CikSubmission` with the given accession + a placeholder form type.
   - Fetch the filing index via `fetch_filing_index`.
   - Find the document whose `document_type` matches `doc_type`.
   - Fetch that document via `Url::CikAccessionDocument`.
3. Advantages: one variant handles all XBRL exhibit types.  The `doc_type` field is human-readable (e.g. `"EX-101.CAL"`) and appears in the fixture list.

### Skip-if-exists logic

Currently the refresh binary always re-downloads every fixture.  The user wants it to skip files that already exist on disk unless they are deleted.

**Change:** At the top of the per-fixture loop, check if the `.gz` file exists:

```rust
let gz_path = fixtures_dir.join(format!("{}.gz", fixture.output));
if gz_path.exists() {
    println!("  {} ({}) — exists, skipping", fixture.output, fixture.ticker);
    continue;
}
```

This makes subsequent runs fast — you only re-download when you explicitly delete a fixture file.

fn parse_bac_calculation_linkbase() {
    let xml = common::fixture_string("BAC_10q_20260331_cal.xml");
    let arcs = sec_fetcher::parsers::parse_calculation_linkbase(&xml).unwrap();

    let xml = common::fixture_string("JPM_10q_20260331_def.xml");

## Part 2 — `indoc!` for inline XML in parser tests

### Background

The existing XML parser tests in `src/parsers/` use `r#"... "#` raw string literals with the XML content left-aligned at column 0:

```rust
let xml = r#"<?xml version="1.0"?>
<link:linkbase ...>
  <link:definitionLink ...>
    ...
  </link:definitionLink>
</link:linkbase>"#;
```

This works but the XML is forced to column 0, making it awkward when nested inside a function body.

### Files to update

| File | Line(s) | XML string count |
|------|---------|-----------------|
| `src/parsers/parse_xbrl_definition_linkbase.rs` | 304-390 | 4 inline XML strings |
| `src/parsers/parse_xbrl_calculation_linkbase.rs` | (check) | 3 inline XML strings |
| `src/parsers/parse_xbrl_label_linkbase.rs` | (check) | 3 inline XML strings |
| `src/parsers/parse_xbrl_extension_schema.rs` | (check) | 2 inline XML strings |

### Change

Replace:
```rust
let xml = r#"<?xml version="1.0"?>
<link:linkbase>
  <link:loc .../>
</link:linkbase>"#;
```

With:
```rust
let xml = indoc! {r#"<?xml version="1.0"?>
    <link:linkbase>
      <link:loc .../>
    </link:linkbase>
"#};
```

`indoc!` strips the leading indentation from the string, so the XML can be indented naturally within the function body.
